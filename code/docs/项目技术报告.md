## 二、系统原理

### 2.1 总体架构

**目标一句话**：在对的时刻、以安全的方式，把对的 POI 推给车里的人。

**唯一模型双通道**（核心设计）：全链路只有一个端侧小模型体系——MLP 负责"说数字"
（把司机上下文编码成 19 类 POI 偏好分布），LLM 负责"说句子"（从合规候选中定稿并给
人话理由）。数字与句子在 prompt 汇合：MLP top3 写进 LLM 输入，LLM 不得违背。
环境/车流/安全约束以 JSON 形式进 prompt 与规则引擎，与模型解耦（模型可替换）。

### 2.2 数据层

1. **轨迹**：T-Drive 北京出租车 GPS（2008-02，10,290 车）→ 质量筛选取 300 辆子集（确定性可复现）
2. **停留事件**：Zheng 口径 200m/15min 提取，等待类剔除
3. **POI 语义图**：OSM（BBBike 北京 pbf）为主键 + 高德 API 属性补充（1,826 条对齐），
   三类节点（POI/道路/区域）+ 五类边（poi-road / poi-poi / IN_REGION / ROAD_CONN / FUNC_COMP）
4. **强制 ID 对齐**：停留 → 最近 POI ≤250m，覆盖率 86.27%
5. **用户画像**：每人一条语义 JSON（节点 ID 序列+到达/离开/时长+时间上下文）

### 2.3 模型层（MLP 说数字）

**特征 64 维**（训练与推理共用 `user_history_features` 同一函数，在线口径防泄漏）：

| 维度 | 内容 |
|---|---|
| 18 维 | 历史停留类别频率（归一化） |
| 3 维 | 停留次数/平均时长/活跃天数 标量 |
| 24 维 | 当前时刻（one-hot 小时） |
| 7 维 | 星期几（one-hot） |
| 11 维 | 所在区域（行政区 adcode 散列；**上一停留所在区**，2026-11-21 修复泄漏后口径） |

**标签**：下一次停留的 POI 类别（19 类）。**划分**：用户级 7:3（同一用户不跨集，seed 42）。
**结构**：MLP 64-128-64-19（Dropout 0.2，Adam lr=1e-3，120 epoch，batch 128）。
**推理口径**与训练完全一致：历史=决策时刻之前的停留；区域=车辆当前位置所在行政区。

### 2.4 决策链（每 20 模拟分钟一次）

| 步 | 内容 |
|---|---|
| ① MLP 说数字 | 历史+时刻+区域 → 19 类概率 → top3 |
| ② 候选召回 | 800m 内 POI ∩ (top3 ∪ 功能互补对) |
| ③ 约束引擎 | 四规则过滤 → 合规集 |
| ④ LLM 定稿 | Qwen2.5-0.5B 从合规集选一个 + 一句理由 |

**三道校验**（防 0.5B 小模型幻觉）：输出必须可解析 JSON；poi_id 必须在合规集内；
有 top3 类候选时定稿必须落在 top3 类内——说句子不许和说数字打架。

### 2.5 约束引擎（四规则，可解释）

| 规则 | 口径 |
|---|---|
| 安全门控 | L0 不限；L1 仅途中即时类+餐饮酒店；L2 仅停车/如厕/便利店/服务区 |
| 营业时间 | 23:00-6:00 景区/体育/学校/影院/购物关闭 |
| 分心约束 | 高速/快速路禁推目的地型 |
| 打扰约束 | 同用户 15 分钟内最多一推 |

### 2.6 疲劳感知（安全信号源）

MediaPipe FaceLandmarker 眼区裁剪 → RGB 学生 CNN（93,825 参数）回归眼睁开度 EAR
（教师 = 几何 EAR 伪标签蒸馏，软目标含模糊带）→ 时间窗 PERCLOS → 安全等级
（<0.2 清醒 / 0.2-0.4 低警惕 / >0.4 疲劳）。外部验证：DDD 留来源 11/12=91.7%；
NTHU 负迁移诚实留档（演员表演困倦无真实闭眼，测量效度问题而非模型问题）。

### 2.7 回放评测（演示内验证）

车辆沿真实 GPS 轨迹 A* 贴路行驶（时间加速），每 20 模拟分钟决策一次，
判卷答案 = 决策时刻之后 3 小时内司机真实到达的第一停留，命中 = MLP top3 含该类别。
预测永远先于答案（口径保证因果），提前量中位 76 分钟。

### 2.8 金标准情景题库（非回放验证）

13 道考题端到端考决策链：约束四规则边界+对照组+组合叠加+冷启动+推送合理性，
金标准确定性判卷，任何人任何时间重跑结果一致；频次基线同卷对照。
景区类前置条件走互补对召回路径（景区从不进任何用户 top3，靠 [scenic,parking] 对进候选，
约束引擎仍须拦截——考的是真实链路而非理想输入）。

## 四、2026-11-21 全量审计结论

### 4.1 修复的问题

| # | 问题 | 级别 | 修复 |
|---|---|---|---|
| 1 | **训练标签泄漏**：区域特征用了预测答案（停留点）自己的所在区，推理时恒零——val top3 54.7% 含水分 | 严重 | 训练改"上一停留所在区"（在线口径），推理用车辆当前位置所在区（行政区射线法点包含）；重训后 val top3 52.5%（诚实值） |
| 2 | 5 个评测脚本主逻辑裸在模块层，被 import 即整轮执行 | 中 | 全部加 `main()` + `__main__` 守卫 |
| 3 | LLM 定稿可与 MLP 预测矛盾（理由说加油站、实选交通枢纽） | 中 | 定稿一致性守卫：有 top3 类候选时定稿必须落在 top3 类内 |
| 4 | 8 个被最终管线取代的实验脚本散在 model/ | 轻 | 移入 `_archive/` |
| 5 | 情景题库前置条件随模型口径漂移 | 轻 | 探针按新口径重探、输入重定（U_10/U_39），13/13 复验 |

### 4.2 验证结果（全部实测）

- 38 个 Python 文件编译通过；21 个模型模块导入检查通过（无副作用）
- **训练可复现性**：重训 120 epoch 精确复现 val top3（best epoch 30）
- 疲劳链路训练/推理一致性核验通过（同架构/同预处理/同阈值）
- 情景题库 --fast 与全链路（含 LLM）均 13/13 通过
- 回放评测/分片对比/提前量按新口径全部重跑，报告 JSON 已更新
- 演示后端端到端冒烟通过（decide 全链路 + 定稿一致性守卫生效）

### 4.3 已知边界与后续方向

1. **时机机制**：定频 20 分钟是简化，后续改"定频+事件混合"（进入服务半径立即决策）+ 时机指标
2. **消融实验**：四组件贡献证据（口径随验证方案已定，可直接执行）
3. **题库扩题**：营业时间事实核对、更多组合场景
4. **模型升级**：特征维度/结构可在统一口径下继续迭代（JSON 解耦保证可替换）
